# 列类型推断与冲突报告（从 0 实现）

起始环境只有本说明、`samples/**` 与 `.gitignore`，没有实现代码。给定一批 CSV 表，逐列推断类型、给出规范化值与冲突清单，并交一个自包含的只读页面；工具用 Python 3.13 标准库实现（入口 `main.py`），页面用原生 HTML/Canvas，无构建、无依赖。

## 一、范围

要做：读入 `--tables` 目录下全部 `.csv`；按下面的口径逐格判型、逐列定类型；每份表输出类型报告 JSON、规范化 CSV、自包含 HTML 页面；冲突报告写出列名、类型组合与证据行。

不做：不解释列名语义；不清洗、不修复、不合并、不去重；不做跨表与跨列推断；不支持 xlsx、json、自定义分隔符、非 UTF-8 编码；不做单位与货币换算；不写回输入目录；不写时间戳与日志；非法输入（表头为空或重复、字段数与表头不一致、非 UTF-8）不纳入验收，可直接报错退出。

## 二、口径与公式

**逐格判定**：字段先去掉首尾 ASCII 空白（空格、`\t`、`\r`、`\n`），空串记为**空值**，不参与判型；其余按下表判型。五种语法互不重叠，优先级从高到低为 `bool` > `int` > `float` > `date` > `text`，只用于类型组合的书写顺序与计数并列时的取舍。

| 类型 | 语法 | 说明 |
| --- | --- | --- |
| `bool` | `true`、`false` | 忽略 ASCII 大小写 |
| `int` | `-?(0\|[1-9][0-9]*)` | 不允许前导零，不写 `+` |
| `float` | `-?(0\|[1-9][0-9]*)\.[0-9]+` | 必须带小数点，不支持科学计数法 |
| `date` | `YYYY-M-D`，分隔符为 `-`、`/`、`.` 或 `年/月/日`（一个值内写同一种） | 必须是合法日历日，年份 0001–9999，含闰年；`2023-02-29` 不算 |
| `text` | 以上都不匹配 | 兜底 |

所以 `007`、`+3`、`1e3`、`.5`、`1.`、`yes`、`no`、`NULL`、`NA` 都是 `text`；`1`、`0` 是 `int`，不是 `bool`。

**列级判定**：记 n 为该列非空格数，T 为该列出现过的类型集合。

- n = 0 → `empty`；n < 3 → `unknown`（样本不足）；这两种都不进冲突清单。
- 否则：T = {int, float} → `float`（数值提升，仍记冲突）；|T| = 1 → 该类型；其余按主导类型定：主导 = 计数最大者（并列取优先级高者），`计数 × 100 ≥ 75 × n`（整数比较）取主导类型，否则 `mixed`。

**规范化**（逐格，按判定的类型）：`bool` → `true`/`false`；`int` → 原样，仅 `-0` 归一为 `0`；`float` → 去掉小数末尾多余的 `0`，小数部分为空就删掉小数点（`2.00` → `2`、`0.10` → `0.1`、`-0.0` → `0`）；`date` → `YYYY-MM-DD`，月日补零；`text` → 去空白后的原文；空值 → 空串。全程按十进制文本处理，不转二进制浮点。

**冲突**：T 里至少两种类型、且非空格数 ≥ 3 的列各一条（`empty`、`unknown` 的列不进清单）；`types` 按优先级从高到低排列（`int`+`float` 也算冲突）；`evidence_rows` 是「类型 ≠ 主导类型」的非空数据行行号（从 1 起、不含表头、升序，最多写 20 个），`evidence_count` 是总条数。

## 三、数据结构

报告 JSON 的字段与顺序固定（与 `samples/expected/01-numeric-mix.json` 同形）：

```json
{
  "table": "01-numeric-mix.csv",
  "row_count": 10,
  "column_count": 4,
  "columns": [
    {"name": "order_id", "type": "int", "null_count": 0, "non_null_count": 10, "type_counts": {"int": 10}}
  ],
  "conflicts": [
    {"column": "unit_price", "types": ["int", "float"], "evidence_count": 5, "evidence_rows": [1, 3, 5, 7, 10]}
  ]
}
```

- `row_count` 是数据行数（不含表头）；`columns` 按表头顺序；`type_counts` 只列出现过的类型、按优先级顺序；`conflicts` 按列在表头中的顺序；`type` 还可能是 `empty`、`unknown`、`mixed`，`types` 只含前五种。
- 序列化：UTF-8 无 BOM、LF、按 `json.dumps(..., ensure_ascii=False, indent=2)` 的写法，键按上面顺序书写（不排序），文件末尾一个换行；同一输入必须逐字节相同。

## 四、输入输出与文件格式

- 入口：仓库根目录 `main.py`，`python3 main.py --tables <输入目录> --out <输出目录>`（Windows 下用 `wsl -- python3 ...`）。`--tables` 只取该目录顶层 `.csv` 文件（不递归、按文件名字符串升序），`--out` 不存在则创建；参数不对或目录不存在时退出码 2；退出码 0 表示全部成功。
- 输入 CSV：UTF-8 无 BOM，行尾 LF 或 CRLF；逗号分隔、RFC 4180 引用规则；首行表头，列名去空白后不得为空或重复；每行字段数须与表头一致。
- 输出：每份 `<x>.csv` 产出 `<out>/<x>.json`、`<out>/<x>.normalized.csv`、`<out>/<x>.html`；均为 UTF-8 无 BOM、LF、末行也带换行。`normalized.csv` 沿用表头与行序，逐格写规范值，含 `,`、`"`、换行的字段按 RFC 4180 加引号。
- HTML：单文件、双击可开；数据以 JSON 字面量内联，不引外部脚本/样式/字体/图片，不 `fetch`、不联网、不构建；用 Canvas 2D 为每列画一根水平条（按类型计数分段，长度与非空占比成比例，空值留底色），并列出冲突表（列名、类型组合、证据行）。类型配色固定：`bool` `#4e79a7`、`int` `#59a14f`、`float` `#f28e2b`、`date` `#e15759`、`text` `#9c755f`，空值底色 `#e8e8e8`；页面不得出现时间戳等易变内容。

## 五、性能与验收口径

预算：单表 ≤ 100 MB、≤ 200 万数据行、≤ 500 列；峰值内存 ≤ 256 MiB 且不随行数增长；单表 60 秒内完成，目录合计 200 MB 时 5 分钟内完成。

1. `python3 main.py --tables samples/tables --out var/out` 退出码 0；每份 `<x>.json`、`<x>.normalized.csv` 与 `samples/expected/` 同名文件逐字节一致（顺序敏感）。
2. 每份 `<x>.html` 存在且自包含（无外部引用、无网络请求），内联数据与 `<x>.json` 一致；同一输入连跑两遍，三类产物逐字节相同，不依赖遍历顺序、哈希顺序、时钟与随机数。
3. 只读输入；只用标准库、无构建步骤；不得读 `samples/expected/**`，不得按样例名或样例内容特判（评测会换表）。
4. 时间与内存满足上面的预算。

## 六、样例说明

`samples/tables/` 共 5 份表，每份与 `samples/expected/` 里同名 `.json`、`.normalized.csv` 一一对应：

| 表 | 覆盖场景 |
| --- | --- |
| `01-numeric-mix.csv` | 整数与小数混排（5:5 并列，主导取 `int`，列类型提升为 `float`）；小数去尾零 |
| `02-date-formats.csv` | 四种日期写法、单位数月日补零、非闰年 2 月 29 日判为文本、字段前后空白与带逗号的引号字段 |
| `03-bool-text.csv` | 布尔大小写、`yes/no` 与 `1/0` 的区分、文本占比 70% 判 `mixed` |
| `04-tail-outlier.csv` | 异常值只在最后两行（含前导零编码判为文本） |
| `05-sparse-null.csv` | 高比例空值、全空列 `empty`、非空仅 2 格判 `unknown`、主导占比恰为 75% |

`samples/notes.md` 是现场记录；`samples/**` 只读，不得改动。
